## The six-layer "full CRM" bar
A CRM template missing ANY layer is the "trash CRM" failure mode. `crm-build-standard` is measured against all six before it ships:
- **A · Platform spine** (per-tenant isolation): `commerce-spine` + `d1-image-store`/R2 + PWA assets + `cf-deploy` — 1 Worker + 1 D1 + 1 R2 per client, on the client's OWN Cloudflare account. Never share a bucket/DB across tenants.
- **B · Security** (fail-closed): `cf-identity` + `clearance-rbac` (unmapped routes default-DENY) + sameOrigin CSRF + `field-encryption-at-rest` + `worker-media-headers` + `idempotent-public-submission`.
- **C · Core CRM + custom fields**: `crm-build-standard` records/pipeline/activities/intake + `custom-fields-engine` (vertical = config/data, never schema code) + `self-schedule-booking` (first-party booking).
- **D · Data lifecycle & sustainability** *(the layer shallow CRMs skip)*: `logical-backup-ndjson-r2` + `r2-upload-budget-guard` + `export-before-delete-reclaim` + `sovereign-store-zip-writer`.
- **E · Presentation** (agnostic): `website-build-standard` + SEO baseline + real photos (`site-media-fetch`) + `universal-i18n-runtime` + a versioned network-first PWA. Editorial, not card-grid slop.
- **F · Engineering discipline**: `d1-proof-harness` + TSC-clean, prove-standalone, browser-verify, no-fake-PASS.
_Trash tells: vertical hardcoded in schema; no auth/clearance/CSRF; blind delete w/o backup; unbounded R2; shared bucket/DB across tenants; plaintext PII; card-grid slop._

## Foundation — almost every build starts here
`cf-identity` → `cf-abuse-guard` → `clearance-rbac` (auth + roles) · `d1-migration-recipes` + `d1-proof-harness` (schema + proof) · `feature-activation-gate` + `append-only-audit-log` (monetization switch + trail) · `vanilla-spa-shell` + `portal-design-system` (UI) · `cf-deploy` (ship) · `video-walkthrough` (deliver the demo).
_Harden it:_ `two-keystore-password-integrity` (tamper-evident hashes + session-epoch logout) · `last-usable-owner-guard` (never lock out the last admin) · `totp-mfa` + `scoped-bearer-token` · `field-encryption-at-rest` (PII columns) · `idempotent-public-submission` (public POSTs).

## Build order (any recipe)
1. **Foundation** — auth + schema + proof harness (+ hardening pack for anything with admin roles or PII).
2. **Spine** — the core CRM / commerce node.
3. **Engines** — the recipe-specific pieces.
4. **Outreach + compliance** — always behind `outbound-compliance-gate` (+ `tcpa-consent-capture` for phone).
5. **Add-on packs.**
6. **Branding + deploy + walkthrough.**
7. **`skill-harvest`** — run it at the end; any net-new capability re-enters the library and this index.
